# 垃圾桶物品堆叠（按类型聚合）实现方案

## 需求（已与你确认）
按 isSimilar 类型聚合一格 · 无限容量 · lore 显示总数 · 放入时+打开时整理 · 不持久化 · 清理/珍贵物品统一聚合 · 逐条目倒计时（创建时计时，追加/取走不重置）· lore 显示剩余时间（去掉全服提醒）· 全部进配置 · 按数量降序 · 重写测试 · 新增 `/eclean trash stats`

## 1. 数据层：重写 `feature/trashcan/TrashcanItemStore.kt`
- 新条目模型 `TrashcanEntry(prototype: ItemStack, count: Long, deadline: Long)`：prototype 是 amount=1 的 isSimilar 键；deadline 为到期时间戳（epoch millis）
- 删除 `maxSlots`、`loadInto/saveFrom`（菜单本就没用它们）
- 新 API：`addItem`（合并到相似条目 `count += n`，**不重置 deadline**；无相似条目则新建；无限容量永真）、`addAll`、`removeItem(prototype, amount)`、`expireEntries(now): Int`（惰性过期）、`getEntriesSorted()`（按 count 降序）、`earliestDeadline()`、`totalCount()`、`entryCount()`、`isEmpty()`、`clear()`
- 构造参数改为 `lifetimeSeconds: () -> Long?`（lambda 运行时读 `Config.current.trashcan.clearIntervalSeconds`，null=永不过期）——顺带修复现有「RuntimeServices.init 早于 Config.load、配置不生效」的时序 bug
- 保留 `ReentrantReadWriteLock`

## 2. 时钟层：改造 `feature/trashcan/TrashcanTicker.kt`
- 删除全局倒计时递减、60/30/10 秒全服提醒（`command.trash_clean_reminder`）、到期 `clearAll()`
- 保留 20 tick 周期任务：`expireEntries(now)` → 有删除则 `TrashcanMenu.updateAllOpen()`
- `countdown` 重定义为「最早到期条目的剩余秒数」，继续写入 `StatusSnapshotService`（PAPI `%eclean_trashcan_countdown%` 兼容，语义变为最早条目到期）

## 3. UI 层：`menu/trashcan/TrashcanMenu.kt` + `TrashcanDisplayItem.kt`
- `rebuildDisplayData()` 改用 `store.getEntriesSorted()`，`TrashcanDisplayItem` 持有 `TrashcanEntry`（含剩余时间）
- lore：`共{amount}个` + 操作提示 + 可选一行 `<gray>剩余 {expire}</gray>`（由 `stacking.showRemainingTimeInLore` 控制，复用 `parseSecondAsDuration`）
- 取出交互不变（左键1 / 右键半组 / Shift一组64），`removeItem` 直接用条目 prototype；打开时 `rebuildDisplayData()` 即完成「打开时整理」
- 分页按钮不受影响（已确认不依赖 countdown）

## 4. 配置：`config/model/TrashcanConfig.kt` + `resources/config/trashcan.yml`
- 新增配置块（带中文注释）：
  ```yaml
  stacking:
    enabled: true              # 聚合开关（false = 每次放入独立条目，不合并）
    sortByCount: true          # 按数量降序排列
    showRemainingTimeInLore: true  # lore 显示剩余存活时间
  ```
- `clearIntervalSeconds` 保留字段名（兼容旧配置），语义改为「每个条目的存活秒数」
- 移除 `maxSlots`（无限容量）；服务器旧配置里的 maxSlots 键会被 kaml 忽略，无迁移问题

## 5. 指令：`command/Commands.kt`
- `handleTrash(sender, args)` 增加 `/eclean trash stats` 分支：要求 `eclean.admin`，逐行输出条目（类型 × 数量 × 剩余时间），空桶给提示；`/eclean trash` 原行为不变
- Tab 补全为 trash 加二级候选 `stats`

## 6. 语言：`resources/lang.yml`
- 新增 `menu.trashcan.item.expire`、`command.trash_stats_*` 键
- 移除不再触发的 `command.trash_clean_reminder`、`command.trash_full`

## 7. 联动点（无需改或仅验证）
- `DespawnListener` / `DropCleanupExecutor`：调用路径不变（addItem 现在永真，溢出丢弃逻辑自然消失）
- `clean/Trashcan.kt` 门面 `countdown` 语义跟随；`clearAll()` 保留（`/eclean clean trash` 手动清空仍可用）
- README 中两个垃圾桶占位符描述更新；`docs/Changelog.md` + `Changelog-zh.md` 新增条目

## 8. 测试
- **重写** `TrashcanItemStoreTest`：聚合超 64、NBT 不同分条目、deadline 创建计时/追加不重置、expireEntries、数量降序、null 永不过期、removeItem/clear/totalCount
- `util.kt` 的 `resetConfig` 用默认 `TrashcanConfig()` 自动适配新字段，无需大改
- 新增 `TrashcanTickerTest`（MockBukkit `performTicks` 驱动条目过期 + UI 刷新）

## 执行顺序
数据层(store) → 时钟层(ticker) → 配置 → UI → 指令/语言 → 测试 → 文档 → `./gradlew test` 全量验证
